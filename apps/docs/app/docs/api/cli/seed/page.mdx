# Seed Command

The CLI exposes a seeding workflow and runtime flags.
## Command Purpose
The seed command runs the repository's data creation workflow. This page explains which script to run, which environment values must exist first, and which flags change the amount of work, batching, concurrency, or debug output.
## How to Run It
Run `bun run seed` from the repository root after dependencies and required environment values are ready.
Install dependencies first with `bun install`.
## What the Command Depends On
The command reads environment-backed configuration. Set these values before using large runs or automation.
- `BATCH_SIZE` (default: `1000`)
- `CONCURRENT_BATCHES` (default: `5`)
- `DEBUG`
- `DEFAULT_PASSWORD` (default: `password123`)
- `EMAIL_DOMAIN` (default: `example.com`) - Optional: Custom domain for emails
- `SUPABASE_SERVICE_ROLE_KEY` (default: `your_service_role_key`)
- `SUPABASE_URL` (default: `your_supabase_project_url`) - Supabase Configuration
- `TOTAL_USERS` (default: `7000000`) - Seeding Configuration
## Flags and Options
Use flags to override defaults for a specific run. Prefer the default script first, then add flags when you need a different scale, concurrency level, target, or debug mode.
- `--batch=NUMBER`: Override batch size
- `--concurrent=N`: Override number of concurrent batches
- `--debug`: Enable debug logging
- `--help`
- `--users=NUMBER`: Override total number of users to seed
